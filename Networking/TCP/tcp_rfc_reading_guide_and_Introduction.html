Section 1

Introduction

RFC 793 contains a discussion of the TCP design goals and provides examples of its operation, including examples of connection establishment, connection termination, and packet retransmission to repair losses.

This document describes the basic functionality expected in modern TCP implementations and replaces the protocol specification in RFC 793. It does not replicate or attempt to update the introduction and philosophy content in Sections 1 and 2 of RFC 793.

Other documents are referenced to provide explanations of the theory of operation, rationale, and detailed discussion of design decisions. This document focuses on the normative behavior of the protocol.

Core purpose The specification concentrates on the protocol behavior that implementations need to follow for basic TCP interoperability.

TCP Roadmap and related specifications

The TCP Roadmap provides a more extensive guide to the RFCs that define TCP and describe important algorithms.

Congestion control Congestion control is a TCP requirement, but its detailed algorithms are outside the basic scope of this specification.
High-performance extensions Many modern implementations support RFC 7323 extensions, although they are not strictly required for basic operation.
Multipath TCP Multipath considerations are specified separately in RFC 8684.
Changes from RFC 793 The document provides a dedicated section listing changes from the original TCP specification.
Section 2.1

Requirements Language

The key words used in this document have precise meanings when they appear in all capitals. They are interpreted as described in BCP 14, including RFC 2119 and RFC 8174.

MUST MUST NOT REQUIRED SHALL SHALL NOT SHOULD SHOULD NOT RECOMMENDED NOT RECOMMENDED MAY OPTIONAL

Why the labels matter

Each use of an RFC 2119 keyword is individually labeled and referenced in Appendix B, which summarizes implementation requirements.

Sentences using MUST are labeled MUST-X. Sentences using SHOULD use SHLD-X, while MAY uses MAY-X and RECOMMENDED uses REC-X.

For this labeling system, SHOULD NOT and MUST NOT follow the same label families as SHOULD and MUST.

Section 2.2

Key TCP Concepts

TCP provides applications with a reliable, in-order byte-stream service. The following concepts describe the core behavior behind that service.

01
Reliable byte stream

TCP provides a reliable, in-order, byte-stream service to applications.

02
Segments and IP datagrams

The application byte stream is carried across the network through TCP segments. Each TCP segment is sent as an IP datagram.

03
Loss and error handling

TCP detects packet loss using sequence numbers and detects errors using per-segment checksums. Lost data is corrected through retransmission.

04
Unicast delivery

TCP supports unicast delivery. Some anycast applications can use TCP without modifications, although lower-layer forwarding changes can create instability risks.

05
Connection oriented

TCP is connection oriented, but it does not inherently provide a liveness-detection mechanism.

06
Bidirectional data flow

Data can flow in both directions over a TCP connection. Applications may still choose to send data in only one direction.

07
Port numbers

TCP uses port numbers to identify application services and multiplex distinct flows between hosts.

Further reading A more detailed comparison of TCP features with other transport protocols is available in RFC 8095. The motivations for TCP and its role in the Internet protocol stack are discussed in Section 2 of RFC 793.
